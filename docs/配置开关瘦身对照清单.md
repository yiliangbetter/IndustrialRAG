# 配置开关瘦身对照清单

> 用途：对照 **env 开关 → 代码分支 → 可删的另一端**，供后续代码瘦身、打包固化、文档归档时查阅。  
> 基准：当前生产 `.env`（本地 HF embed + Qwen rerank + mix + 文本灌库 + 澄清路线 2 + Web 题末 release）。  
> 最后核对：2026-07-03。

---

## 1. 如何使用本文档

| 列 | 含义 |
|----|------|
| **当前值** | 仓库根 `.env` 中的典型生产配置 |
| **默认值** | 代码里 `getenv` 未设置时的 fallback |
| **活跃分支** | 当前配置实际走的路径 |
| **休眠分支** | 开关另一端、长期不用的实现 |
| **瘦身优先级** | 高 / 中 / 低（见下表） |
| **主代码位置** | 读 env 或分支判断的文件与函数 |

**优先级**

| 标记 | 含义 |
|------|------|
| **高** | 分支大、与生产路径冲突明显，删后收益高 |
| **中** | 另一端长期不用，但 A/B、批测、云端部署可能还要 |
| **低** | 产品/运维开关、阈值调参，或仅注释/死配置残留 |

**建议瘦身顺序**见 [§10](#10-建议瘦身批次)。

## 2. 当前生产路径一句话

```
EMBEDDING_BACKEND=hf
  → local_hf_embedding.py（单例，无 release API）
RERANK_BINDING=hf + RERANK_RELEASE_AFTER_QUERY=1（Web）
  → pipeline_rerank.py CrossEncoder；题内 gate+aquery 共用，题末 release
RAG_QUERY_MODE=mix + RAG_CLARIFY_ENABLED=true + CLARIFY_CANDIDATE_SKIP_PROBE=1
  → 澄清路线 2：原问 probe + 推荐 LLM-only，keep_original 注入 bundle
RAG_WEB_SKIP_MULTIMODAL=1
  → 灌库仅文本
RAG_LLM_RERANK_FIGURE_SUPPLEMENT=0 + RAG_IMAGE_ANCHOR_MODE=answer
  → 配图不补 rerank 池，answer 锚扫描
```

## 3. 澄清门控

**设计文档**：`docs/澄清门控实现说明_v4.md`、`docs/澄清门控优化路线.md`  
**主模块**：`raganything/clarify_gate.py`  
**Web 接入**：`scripts/rag_web_server.py`（`_evaluate_clarify_gate`、`_inject_clarify_bundle_for_bypass`）  
**Bundle 注入**：`scripts/query_progress_hooks.py`（`set_clarify_context_injection` → `clarify_inject` 跳过 retrieve+rereank）

### 3.1 总开关与模式

| 环境变量 | 当前值 | 默认 | 活跃分支 | 休眠分支 | 优先级 | 代码位置 |
|----------|--------|------|----------|----------|--------|----------|
| `RAG_CLARIFY_ENABLED` | `true` | `false` | 走 `evaluate_clarify_gate` | `ClarifyBypass("disabled")` 直 `aquery` | 低 | `is_clarify_gate_enabled()` |
| `CLARIFY_ONLY_NAIVE_MODE` | 未设 | `false` | mix 下门控开启 | 仅 `mode=naive` 才门控 | 中 | `is_clarify_gate_enabled(mode)` |
| `RAG_QUERY_MODE` | `mix` | `mix` | mix 检索+图谱 | naive/local/global/hybrid | 低 | LightRAG `QueryParam.mode`；UI 可改 |

### 3.2 路线 1 vs 路线 2（核心）

| 环境变量 | 当前值 | 默认 | 活跃分支 | 休眠分支 | 优先级 | 代码位置 |
|----------|--------|------|----------|----------|--------|----------|
| **`CLARIFY_CANDIDATE_SKIP_PROBE`** | **`1`** | `false` | **路线 2**：推荐 `_append_llm_only_candidate`，`bundle=None`；点选 `use_candidate` → 全量 `aquery` | **路线 1**：`_collect_high_confidence_candidates` 内 `probe_llm_retrieval_full` 每条推荐，`options[cid].bundle` 缓存注入 | **高** | `clarify_candidate_skip_probe()`；`642–760` 行循环 |
| `CLARIFY_CANDIDATE_MAX_PROBES` | 已注释 | 无=不限 | — | 路线 1 时限制 probe 次数 | **高** | `clarify_candidate_max_probes()`；`SKIP_PROBE=1` 时**完全不读** |
| `CLARIFY_CANDIDATE_STRATEGY` | `fill_k` | `fill_k` | 凑满 `CLARIFY_CANDIDATE_K` 条 | `first`：第一条可用即停 | 中 | `_candidate_generation_batch_size()`；`712–722` |
| `CLARIFY_CANDIDATE_K` | `2` | `2` | 推荐条数 | — | 低 | `clarify_candidate_k()` |
| `CLARIFY_CANDIDATE_MAX_ROUNDS` | `1` | `3` | LLM 生成轮次上限 | — | 低 | `clarify_candidate_max_rounds()` |
| `CLARIFY_DIRECT_RERANK_MIN` | `7` | `7` | `final_score > 7` 直答 | ≤7 进澄清 | 低 | `clarify_direct_rerank_min()`；`_probe_passes_direct_threshold` |
| `CLARIFY_CANDIDATE_MIN_RERANK_SCORE` | 未设 | 回退 `MIN_RERANK_SCORE` | 与 `MIN_RERANK_SCORE` 对齐 | — | 低 | `clarify_candidate_min_rerank_score()` |

**路线 2 相关代码路径**

```
evaluate_clarify_gate
  → _evaluate_clarify_gate_probed（原问 probe，保留）
  → _collect_high_confidence_candidates
       skip_probe=True → _append_llm_only_candidate（无 bundle）
  → _register_clarification（存 original_bundle + options）

用户点 keep_original:
  resolve_clarify_bundle → original_bundle
  → set_clarify_context_injection → aquery 跳过检索

用户点 use_candidate（路线 2）:
  resolve_clarify_bundle → bundle=None → 全量 aquery
  candidate_bundle_consumed / _consume_candidate_bundle 仅路线 1 有效
```

**路线 1 可删块（瘦身时对照）**

| 符号/函数 | 文件 | 说明 |
|-----------|------|------|
| `probe_llm_retrieval_full` 候选循环 | `clarify_gate.py` `725–760` | `skip_probe=False` 分支 |
| `options[cid].bundle` | `clarify_gate.py` `option_entries` | 候选缓存 |
| `_consume_candidate_bundle` | `clarify_gate.py` `424+` | 路线 1 按候选消费 |
| `candidate_bundle_consumed` | `clarify_gate.py` `446+` | 路线 1 防重复点选 |
| `CLARIFY_CANDIDATE_MAX_PROBES` | env + `clarify_candidate_max_probes()` | 路线 1 专用 |

**已知缺口（路线 2）**：`use_candidate` 二次点击仍会全量 `aquery`（无 `candidate_used` 服务端标记）；前端 `web/static/app.js` `markClarifyOptionUsed()` 仅 UI 禁用。

### 3.3 门控与 rerank 释放

| 环境变量 | 当前值 | 活跃 | 休眠 | 优先级 | 代码位置 |
|----------|--------|------|------|--------|----------|

## 10. 建议瘦身批次

### 第一批（高，与澄清路线 2 + 死配置）

1. 固定 `CLARIFY_CANDIDATE_SKIP_PROBE=1`，删除路线 1 probe/bundle 分支  
2. 删除 `CLARIFY_CANDIDATE_MAX_PROBES` 及 `clarify_candidate_max_probes()`  
3. 路线 2 增加 `candidate_used`；简化 `resolve_clarify_bundle` / `candidate_bundle_consumed`  
4. 删除 `RAG_USE_CLARIFY_UPPER_AS_MIN_RERANK` 分支  
5. 从 `.env` / `env.example` 移除 §7.1 死配置  
6. 删除或归档 `scripts/.checkpoint_wip_full/`

### 第二批（配图 + steering 默认固化）

7. 固定 `RAG_LLM_RERANK_FIGURE_SUPPLEMENT=0`，删 supplement 主路径  
8. 核对 `RAG_IMAGE_TRUST_LLM_CHUNKS` 默认与文档  
9. 将默认常开的 steering（`CONCISE_FACT`、`KG_STEERING`、`CATALOG_*`）写入打包模板或去掉开关只留默认 `true`

### 第三批（后端绑定）

10. `RERANK_BINDING` 仅保留 `hf` + `none`  
11. `EMBEDDING_BACKEND` 仅保留 `hf`（客户端路径已 `setdefault`）  
12. Release 三开关：Web 文档固定「题末 QUERY=1」；批测脚本显式说明

### 第四批（低，保留产品能力）

13. `PARSER` 多实现、`RAG_QUERY_MODE` 多模式、多模态 UI 开关、开发 dump

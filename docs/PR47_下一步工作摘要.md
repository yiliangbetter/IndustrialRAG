## 4. 配图去 hardcode 方案（image_query_refs，A+B 耦合，C 增强）

> **2026-07-29 定稿**（用户已认可 A+B，C 列为后续增强）。承接 §B 剩余唯一代码工作。

### 4.1 核心思路：配图 ↔ 灌库耦合

现状两者**脱耦**：灌库侧 `induce_field_schema`（`raganything/ingest_coalesce.py`）已归纳每篇文档的字段角色（initiator/closer/metadata_keys），但**只在 coalesce 期间临时用、不落库**；落库 chunk 仅带 `file_path` + 极简 metadata。于是查询侧配图只能事后用 hardcode 反推（机型词表 `_KNOWN_MACHINE_NAMES`、字段名/话术正则）——灌库算过、查询又用 hardcode 重猜一遍。

**方向**：把灌库已算出的机型 / 字段 schema **持久化**，查询侧直接读，hardcode 从“查询侧猜”变为“灌库一次算清、查询直接读”，复杂度移到最该待的灌库侧。

**前提：需重灌**。当前 KV 灌于 2026-07-10，已落后于灌库代码（`a023f3f` / `e5a5328` 在 07-28），重灌本就不可避免，正好趁此把元数据落库。

### 4.2 hardcode 清单（按难度）

| 项 | 位置 | 内容 | 难度 |
|----|------|------|------|
| 机型名词表 | `iqr_figure_target.py:546` | `_KNOWN_MACHINE_NAMES`（6 机型）+ `_resolve_known_machine_name` | 🔴 高 |
| 机型反串扰特判 | `iqr_store.py:63-77` | 高速智能 vs 高速自动 / 自动封边机 子串互串特判 | 🔴 高 |
| 答案模板字段名 | `iqr_figure_target.py:556/577` | `_ANSWER_STRUCTURAL_LABEL_KEYS`（14 个）/ `_COMPONENT_FIELD_KEYS` | 🟡 中 |
| 保养话术正则 | `iqr_figure_target.py:100-107` | `_MAINT_TOPIC_RE` / `_GENERIC_CYCLE_LABEL_RE` / `_MAINT_CYCLE_VALUE_RE` | 🟡 中 |
| 目录型号标记 | `iqr_figure_target.py:116` | `_CATALOG_MODEL_MARKER`（已有 env 兜底） | 🟢 低 |

落库载体：chunk metadata（`raganything/ingest_insert.py`）或 content_list item（`data/pipeline_parse/*_content_list.json`）；机型亦可从文档名派生（doc_hint 已取自手册名）。

### 4.3 耦合方案

**A. 机型落 metadata（🔴，先做）**：灌库写入 `machine`（文档名派生 / schema 归纳顺带）→ 查询侧删 `_KNOWN_MACHINE_NAMES` + iqr_store 反串扰特判，直接读 `doc.metadata["machine"]`；反串扰保留“去空格最长前缀匹配”通用算法兜底。

**B. 字段 schema 落库（🟡）**：coalesce 已归纳的 `DocFieldSchema` 持久化进 chunk metadata → 查询侧删 `_ANSWER_STRUCTURAL_LABEL_KEYS` / `_MAINT_TOPIC_RE` 等话术正则，直接读 schema 字段角色；归纳失败 → 保守降级（沿用 `schema=None` no-op 范式）。

**C. 图谱承载（增强项，后续评估）**：机型作为图谱实体 + “适用机型 / 保养部件”关系 → 跨手册列举配图（Q16/Q17 类）从图谱取，不靠答案解析硬拼。**前提**：图谱质量达标；作为 A+B 之后的增强，非本轮必做。

### 4.4 瘦身（配合去 hardcode）

- facade 砍内部 re-export：`image_query_refs.py` 公共 API 仅 `__all__` 14 个，却 re-export 数百内部 `_` 符号 → 只导出公共符号（378 → ~80 行）；先扫描确认无外部脚本直接 import 内部符号。
- `iqr_figure_target.py`（3116 行）二次拆分：机型识别（→`iqr_machine`）/ 答案结构解析 / 跨手册列举配图。
- 合并重复谓词：大量 `_ref_*_gate` / `_chunk_*_score` 为“term overlap + 阈值”变体 → 抽公共 predicate 参数化。
- 清理各模块“auto-generated, do not hand-edit”搬家注释（停用 `scripts/_tmp_iqr_gen.py` 后）。

### 4.5 执行顺序与风险

顺序：**A（机型落库 + 反串扰）→ B（字段 schema 落库）→ 瘦身**；**C 列为后续增强**；配合全量测试脚本重写（§3 步骤4）回归。

风险：
- 机型落库直接决定配图召回/精度，需测试保护（旧测试脚本将随 PR47 重写，先重写测试再动 A）。
- 反串扰最易回归，放最后 + 保留通用算法兜底。
- 字段 schema 依赖答案格式稳定，降级须保守。
- 新增 metadata 字段须确认不破坏协议序列化（参考灌库链路边界：仅 coalesce 环节扩展，其余不动）。

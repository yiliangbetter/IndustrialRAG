## 3. 与设计稿的差异（已知偏差）

### 3.1 可答判定用的 chunk 来源

| | 设计稿 | 当前实现 |
|---|--------|----------|
| 可答定义 | rerank ≥ 0.28 的 **document chunks**（与送 LLM 的 Document Chunks 段一致） | `get_llm_input_chunks()`，经 **`RAG_QUERY_DOC_FILTER`**（`filter_retrieved_docs_by_query`）后的列表再数 rerank |
| bundle 内容 | 同批 document chunks | `raw_data["data"]["chunks"]`（LightRAG 构建结果，**未经** doc filter） |

**可答统计走 filter 后快照**（`probe` 内 `_summarize_llm_chunks(chunks)`，`chunks = get_llm_input_chunks()`）。

**bundle 走 raw_data 全量 chunks**（`build_cached_bundle` 入口）：

```132:145:raganything/clarify_context.py
def build_cached_bundle(
    query: str,
    *,
    context_str: str | None,
    raw_data: dict[str, Any] | None,
) -> CachedQueryBundle:
    ...
    data = (raw_data or {}).get("data") or {}
    chunks = data.get("chunks") or []
```

doc filter 在 hook 里只改 `_llm_chunks_for_images`，不改 `raw_data`：

```457:483:scripts/query_progress_hooks.py
def _sync_llm_chunks_for_images(query: str, chunks: list[dict]) -> None:
    ...
        filtered = filter_retrieved_docs_by_query(query, chunks)
        final = filtered if filtered else chunks
    ...
    _llm_chunks_for_images.set(merged)
```

影响：

- 门控可能比设计 **更严**（doc filter 滤光后 `chunk_count=0` → 拒答，而 `raw_data` 里仍有 chunks）
- dump / replay 报表里的 `original_llm_chunks` 与 bundle 内 chunk 条数 **可能不一致**

设计稿 §11.5 已预警；**当前未改代码**，以 hook 快照为准。

### 3.2 类型命名

设计建议 `ClarifyReject` / `ClarifyOffer`；实现统一 `ClarifyRequired`，靠 `gate_outcome` 区分。对外 JSON 契约已按设计提供 `gate_outcome`。

### 3.3 拒答 A 与 A′ 的前端区分

设计区分「无关拒答」与「推荐凑不齐」；实现两种均 `unrelated=true`，前端都不出按钮。产品若需不同样式，可后续仅改 A′ 的 `unrelated` 或加 `gate_reason` 分支样式。

### 3.4 replay 原问 probe 统计（已对齐 Web）

replay 的 ``original_llm_chunks`` / ``original_answerable`` 取自 ``evaluate_clarify_gate`` 返回的 ``gate.data["original_probe"]``，与 Web 单次门控 probe **同源**，不再额外 pre-probe。

```126:141:scripts/replay_clarify_gate_green8.py
    gate = await evaluate_clarify_gate(rag.lightrag, orig_q, mode=mode)
    clarify_triggered = isinstance(gate, ClarifyRequired)
    orig_probe: dict[str, Any] = (
        (gate.data.get("original_probe") or {})
        if isinstance(gate, ClarifyRequired)
        else {}
    )
    ...
        "original_llm_chunks": int(orig_probe.get("chunk_count") or 0),
        "original_answerable": bool(orig_probe.get("answerable")),
```

``original_probe`` 由 ``_probe_summary()`` → ``RetrievalProbeResult.as_stats()`` 填充（含 ``llm_chunk_total`` / ``scores_unavailable``）。早期 replay 曾 pre-probe 一次导致报表与 ``gate_outcome`` 偶发不一致（如 voice29 #23）；该问题已消除。

### 3.5 其他

- **`chunk_tracking`**：设计 §4 可选字段，未写入 dump。
- **`CLARIFY_THRESHOLD`**：代码保留兼容 stub（`clarify_threshold()` 恒 0.6），**门控不再读取**。
- **Injection 后配图**：`get_llm_input_chunks()` 在 injection 路径下来自 bundle 捕获的快照；若开启 doc filter，答题阶段配图仍可能走 filter 逻辑（与门控 probe 口径相同）。

replay 在 `_replay_case` 末尾调用：

- 用 `voice_script_tests.json` 里每题的 `grade.text_any` / `text_all` 与 **最终答案** 做关键词匹配
- **PASS**：命中标准要点；**FAIL**：未命中（`grade_miss` 列原因）

与门控无关：

| 字段 | 含义 |
|------|------|
| `gate_outcome` | 澄清门控结果 |
| `has_answer` | LLM 是否生成非空回答 |
| `grade_ok` | 答案是否覆盖话术标准要点 |

replay **固定选 c1**，推荐问角度常与原问/标准答案不同，故 grade 全 FAIL **不表示门控或 RAG 检索失败**。

shili17 多数题无 `grade` 配置 → `grade_miss: 无评分要点`，同样记 FAIL。

### 7.3 常见问题

**Q：有 KG 实体但拒答？**  
v3 原问 chunk=0 即拒答，不再 KG-only 答题。

**Q：原问可答但不想澄清？**  
v3 无「长问直通」；原问可答且凑满 k 必出 Offer。

**Q：报表 chunks=0 却是 offer？**  
replay 已与 Web 对齐为单次门控 probe；若仍出现，说明该次 probe 判定原问可答（``original_probe.chunk_count > 0``），与 ``gate_outcome`` 一致。历史批测中 #23 类矛盾来自旧版 replay 双 probe，已修复。

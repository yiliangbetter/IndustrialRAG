# 澄清门控 gate 耗时不稳定 — 诊断报告

> 日期：2026-06-29  
> 环境：Windows · RTX 3080 Laptop · `RERANK_MODEL=Qwen/Qwen3-Reranker-0.6B` · `EMBEDDING` bge-m3 CPU · `CLARIFY_CANDIDATE_SKIP_PROBE=1`（路线 2）  
> 关联：`docs/澄清门控优化路线.md` · 后续优化方案：[`docs/澄清门控Qwen_rerank优化方案.md`](./澄清门控Qwen_rerank优化方案.md)

---

## 1. 现象

green8 批测（`bench_clarify_green8_20260629_214557`）中 **gate 时间极不稳定**：

| 指标 | 数值 |
|------|------|
| gate（原问→门控/推荐） | min **17s** · med **1min41s** · max **6min43s** · avg **2min33s** |
| answer（点选→LLM） | min **1min13s** · med **2min23s** · max **6min50s** |
| outcomes | direct=1 · offer=5 · reject=2 |

用户怀疑「越跑越慢」及显存占用问题。后续通过 **4 组诊断** 对比验证。

## 2. 诊断方法与原始报告

| # | 命令 / 脚本 | 报告路径 | 目的 |
|---|-------------|----------|------|
| D1 | `bench_probe_timing_green8.py`（用户自跑） | `logs/bench_probe_timing_green8_20260629_225204.txt` | 仅 probe，排除答题 LLM |

## 3. 核心结论（摘要）

1. **瓶颈在「LightRAG 进程内的 Qwen rerank」**，不是推荐 probe（路线 2 已为 0）、也不是推荐 LLM 生成（~10–18s 稳定）。
2. **不是显存泄漏**：VRAM 全程约 **14–16GB**，不随题数单调上涨。
3. **孤立 rerank 非常稳定**（~7.5s / 79 chunk × 8 轮）；**同一 Python 进程内** rerank batch 可从 **~3s 劣化到 90–180s**。
4. **full bench（gate + 长 LLM 答题串行）** 比 probe-only / gate-only **再慢 2–6 倍**（#14、#28 最明显）。
5. **次要因素**：mix 模式 **LLM 抽关键词不稳定**（#7 同问第二次 +285%），改变 KG 路径并叠加 rerank 劣化。

读表要点：

- **full bench >> probe-only**（#28：56s vs 322s）→ **答题 LLM 与下一题 probe 串行** 显著放大波动。

## 6. 显存与孤立 rerank

### 6.1 VRAM（D1 / D2）

- `nvidia-smi` 报告：**14378–16112 MB**，题间 **无单调增长**。
- **排除**：典型显存泄漏导致 gate 越来越慢。

### 6.2 孤立 rerank 压测（D3）

```
模型: Qwen/Qwen3-Reranker-0.6B
pool: 79 chunks · batch_size: 32 · 8 轮
total_s: min=7.3 med=7.5 max=7.6
round2/round1 = 1.01 · max/round1 = 1.04
nvidia_peak_mb ≈ 8431
```

**解读**：Fresh CrossEncoder、无 LightRAG 时，Qwen rerank **稳定 ~7.5s/轮**，无劣化。

---

## 7. 进程内 rerank 劣化（日志证据）

LightRAG 日志中 **同一 session** 的 CrossEncoder batch 耗时：

| 阶段 | 题目 | rerank batch 耗时 | 合并池 | 备注 |
|------|------|-------------------|--------|------|
| 冷启动 | #2 | ~2.5–4s / batch，共 ~9s | ~72 | 首次加载 CE |
| 温态 | #4 (gate-only) | **56s + 30s + 17s** | ~91 | 仅 rerank ~69s |
| 热态 | #14 (gate-only) | **149s + 96s + 52s** | ~66 | 仅 rerank ~297s |
| repeat2 | #14 第2次 | **183s + …** | ~64 | 同问仍慢 |

对比 D3 孤立 **7.5s / 79 chunk**，进程内同量级 pool 可出现 **分钟级** rerank → **主因是长进程 + GPU 上的 Qwen CE，而非 merge 逻辑本身**。

可能机制（待进一步隔离）：

- Laptop GPU **热节流**（3080 Mobile 长负载）；
- **CUDA 上下文**长期占用 + CPU embed 与 GPU rerank 交替；
- **sentence_transformers CrossEncoder** 长会话行为（孤立压测每次新建实例则正常）。

---

## 8. 次要因素：mix 关键词不稳定

#7「靠板上限？」repeat2：

- 第 1 次：~32s，keywords 较丰富，pool=80  
- 第 2 次：**122s**，keywords 收缩（日志仅「靠板」），pool=64  

短口语题在 mix 模式下 **LLM 抽词有随机性**，会改变 entity/KG 检索路径；与 rerank 劣化叠加后 gate 时间可差 **3–4 倍**。

---

## 9. full bench 为何最慢

典型串行（214557）：

```
#11 gate 45s → answer 410s → #14 gate 385s → answer 173s → #26 … → #28 gate 322s
```

- **长 LLM 答题**（云端 API + 本地 GPU 可能仍驻留 rerank 模型）后，下一题 probe 的 rerank batch 已处于「热态/劣化」区间。
- D1 probe-only 无 answer：#14 **175s**、#28 **56s**，远低于 full bench 的 **385s / 322s**。

## 10. 优化建议

### 10.1 立即可做（配置 / 跑法，无需改代码）

| 优先级 | 措施 | 预期效果 |
|--------|------|----------|
| P0 | **gate 与 answer 分离**（批测用 `--gate-only`；线上点选后再 aquery） | 消除 410s 级答题对下一题 probe 的干扰 |
| P0 | **路线 2 已启用**（`CLARIFY_CANDIDATE_SKIP_PROBE=1`，推荐只生成 k=2 条） | 已去掉推荐 rerank probe；推荐 gen ~10s |
| P1 | **对比 BGE v2-m3 作 gate rerank**（同 `bench_probe_timing --repeat-each 2`） | 孤立压测 BGE ~2.7s vs Qwen ~7.5s；需验证 in-process 是否也劣化 |
| P1 | **题间 `cuda.empty_cache()`**（`bench_probe_timing --gc-between`） | 验证能否缓解 #14 类 repeat 漂移 |
| P2 | **embed/rerank 设备策略**（如 rerank 改 CPU 或统一 GPU 并留冷却） | 减轻 GPU 争用/热节流（需实测） |

### 10.2 中期（需改代码）

| 措施 | 说明 |
|------|------|
| **澄清专用轻量 probe** | 门控只需 `final_score` 三档；可 naive+rerank 或缩小 TOP_K / entity chunk 上限 |
| **短句 keyword 稳定** | ≤N 字口语题用原问作 keyword，或缓存 LLM 抽词结果 |
| **子进程隔离 probe** | 每题独立进程跑 `aquery_data`，结束释放 CUDA；代价是模型加载 ~2s/题 |
| **题间 reload CrossEncoder** | 在 `pipeline_rerank` 层可选「每 N 次 predict 重建 CE」 |

### 10.3 不建议作为首选

- **继续全局降低 `MIN_RERANK_SCORE`**：与 Q17/Q14 检索质量 tradeoff 无关，不解决 gate 耗时。
- **单纯加大 `CHUNK_TOP_K`**：不解决 rerank 劣化。
- **归因于显存泄漏**：诊断数据不支持。

## 12. 一句话结论

**gate 耗时不稳定的主因是：LightRAG 长进程内 Qwen CrossEncoder rerank 随连续 query 显著变慢（非显存泄漏）；full bench 中 gate 与长 LLM 答题串行进一步放大波动；mix 关键词随机性是 #7 类短句的次要因素。** 优先 **gate/answer 分离**、**评估 BGE gate rerank**、**题间释放 GPU 或子进程 probe**；中期再做 **轻量 probe 路径** 与 **keyword 稳定**。

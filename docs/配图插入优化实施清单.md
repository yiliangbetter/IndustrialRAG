> **策略**：优先 **P2 治本 + 重灌**；P1 为查询侧补丁，**P2 回归通过后可不做**。

## P0：Web 机型区块 h3 定位（已完成）

**根因**：`findSectionHeading` 使用 `got.includes(want)`，「自动封边机」被「高速自动封边机」抢先匹配。

**改动**：`web/static/app.js`

- 新增 `machineSectionHeadingIndexAtOffset`、`answerBodyH3Elements`
- `findSectionHeading`：先 exact match；失败时用 markdown 中 `###` 序号对应 DOM h3（排除 References）

**验证**：重问 Q17，确认 `### 自动封边机` 下激光 bullet 后有图；高速自动区块不应叠两张激光图。

---

## P0.5：跨手册同 caption dedup + References 兜底（已完成）

**根因（Q16 透平油）**：答案无 `### 机型` 标题，三条 placement 均落 section `"_"`；三图 caption 相同 → 只保留第一张；inline 全失败时 `appendChild` 到答案容器末尾 → 图出现在 References 后。

**改动**：`web/static/app.js`（非领域词表）

- `imageDisplayDedupKey`：`source_key` 手册维度 + caption（caption 过短则用 URL）
- `appendFiguresToAnswerEnd`：有 `### References` 时在其 `h3` 前插入，否则仍 append 末尾
- `insertFigureAfterAnchor`：`marked breaks` 下多行 `<p>` 内按 `<br>` 行后插入（不再提升到整段 `<p>`）；批量插入逆序避免 DOM 漂移

**验证**：Q16 三机型各 1 张；Q11 三部件仍 3 张；Q17 各 `###` 区块行为与 P0 一致。

## P1：查询侧 sibling inline-figure 桥接（暂缓）

**定位**：**症状补丁**，不是根因修复。当初为 Q17「双端涂胶轴漏图」设计——灌库已拆成字/图 sibling，retrieval 只 cite 无图块时，在 **cite_pool 内**桥到带 `[图片]` 的 sibling（不从全库 KV 强补）。

**根因（与 P2 同源）**：`coalesce_text_image_segments` 只合并紧后 `[图片]`；双端 p7 等版式下文字行先成 chunk，图挂在后续多图 chunk（如 `chunk-76122b630` / `chunk-3040519ad` 纯字，`chunk-9e61a224` 带 `740143cf` 未进 cited 池）。

**已有部分能力**：`image_query_refs.py` 对 listing 题有 `inline_figure_citation_keep`（`_chunk_aligns_answer_bullet_via_inline_figure`），范围窄，**不等于**完整 P1。

**与 P2 关系**：

| | P2（灌库） | P1（查询） |
|---|-----------|-----------|
| 作用 | 同一 anchor 正文 + `[图片]` 尽量共 chunk | 已拆开时，cite 无图块 → 在 cite_pool 找 sibling |
| 重灌 | 需要 | 不需要 |
| Q17 双端涂胶轴 | 治本，**largely 可替代 P1** | 不重灌时的兜底 |

**决策**：**优先做 P2 并重灌**；用 Q17（双端涂胶轴）、Q3、Q4 回归。若 P2 后 cited chunk 自带图、漏图消失，**P1 可取消**，不必再做 query 侧专项桥接。

**若仍要做 P1**：复用 `_chunk_aligns_answer_bullet_via_inline_figure` 等；限制在 cite_pool / cited_manual_kv_pool 内扩展。

## P2：灌库分段（待做，需重灌）

**统一根因**：`coalesce_text_image_segments`（`raganything/utils.py`）只合并 **紧挨着的** `[图片]`；parser 阅读顺序下，标题行、表格/list 短行、正文与图之间若夹块或版式错位，会切成 **纯文字 chunk** 与 **带图 sibling chunk**，进而导致：

- **检索/LLM**：相邻节（如 2.1.1 / 2.1.2）同进 top-K，答案混写；
- **配图**：cited 无图 sibling，或 `answer_topics` 跟错节（Q3 配到「清洁机床内部」）。

**改动方向**（非领域词表）：

- 同页相邻短 text segment 轻量合并后再 coalesce；
- 或 `best_image_for_text_item` / `context_text_for_image` 结果回填到对应 text segment，修正 `关联正文` 串节。

### 用例 A：双端 p7（原 Q17 漏图）

| 现状 | 目标 |
|------|------|
| 涂胶轴等步骤文字 → 纯字 chunk | 步骤正文 + 对应 `[图片]` **同一 chunk** |
| 图挂在后续「轴承润滑」等多图 chunk | `关联正文` 对齐本行 anchor，不串到别节 |

**验证**：Q17 双端「涂胶轴」有图；文字仍对。

### 用例 B：高速智能 p5 — 2.1.1 / 2.1.2（Q3 / Q4）

| chunk | 现状问题 | 目标 |
|-------|----------|------|
| `2.1.1 机床床身清洁` | 标题 **orphan**，无周期、无步骤 | 标题 + 外部清洁正文 + **「每天保养一次」** + 图「机床外部清洁」共 chunk（或标题与正文 inseparable 合并） |
| 2.1.2 内部清洁 | 与 2.1.1 并列进检索；`关联正文` 串进 2.1.1 表述 + 图注「清洁机床内部」 | **独立 chunk**；`关联正文` 仅 2.1.2，不串 2.1.1 |
| 2.1.1 正文 + 外部图 | 与 2.1.2 步骤相似，易被混 cite | 检索问「床身清洁 / 多久」时，**2.1.1 块自洽**，LLM 不必借 2.1.2 作答 |

**验证**：

- **Q3**：文字「每天保养一次」；配图「机床外部清洁」（非「清洁机床内部」）；答案不必扩写 2.1.2 步骤。
- **Q4**：配图「清洁机床内部」；与 Q3 图注不混。

**因果说明（Q3）**：失败链为「2.1.2 chunk 进 LLM → 答案写出功能单元等步骤 → `answer_topics` 选错图」。P2 守住节边界后，该链在源头断开；**不另做 query 侧 P1.5 类专项**。

### 重灌范围

至少：**双端封边机维护保养手册**、**高速智能封边机维护保养手册**；其他表格/list 或同页多节版式机型视 diff 一并重灌。

**注意**：改 ingest 后必须重灌受影响手册；查询/Web 侧无需为 P2 改代码（P0/P0.5 已完成的 Web 插入逻辑保持不变）。

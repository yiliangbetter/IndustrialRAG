# 文档解析、灌库与图谱问答（脚本使用说明）

对应脚本：**[`scripts/rag_pipeline_parse_graph_chat.py`](../scripts/rag_pipeline_parse_graph_chat.py)**（仓库内英文文件名不变，终端里仍用这个路径运行）。

本文档说明该脚本的用途、命令行参数、环境变量与典型用法示例。

## 脚本做什么

端到端流程：**MinerU（或可配置的解析器）解析文档 → 将 `content_list` 写入 LightRAG 知识图谱（`insert_content_list`；默认 **`--skip-multimodal`** 为文本优先，表格正文会拼入纯文本再索引；若使用 **`--no-skip-multimodal`** 则走表格/图片/公式等多模态处理器）→ 交互问答或单次提问**。

运行前请已在仓库根目录配置 **`.env`**（脚本固定从 **仓库根目录** 加载 `.env`，与你在终端里的当前目录无关）。

## 前置条件

- **Python**：建议与项目要求一致（≥3.10）；推荐使用 **`uv`**。
- **依赖**：在仓库根目录执行 `uv sync`；本地向量可选 `uv sync --extra local-embed`。
- **密钥与模型**：至少需要可用的 **LLM API**；向量侧可为 OpenAI 兼容接口或 `EMBEDDING_BACKEND=hf` 本地模型（详见下文环境变量）。
- **解析**：默认 **`PARSER=mineru`**；首次解析可能需要下载 MinerU 权重（可用 `--mineru-download-models` 预先拉取）。

## 如何调用

在**仓库根目录**执行（示例统一使用 `uv run python`，也可用激活虚拟环境后的 `python`）：

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py --help
```

Windows PowerShell 下路径可写成 `.\scripts\rag_pipeline_parse_graph_chat.py`，参数相同。

## 命令行参数一览

| 参数 | 说明 |
|------|------|
| `--input-folder` | 待处理文档所在文件夹（PDF、Office、图片等，扩展名受配置约束）。**使用 `--query-only` 时可省略。** |
| `-w` / `--working-dir` | **LightRAG 持久化目录**（图谱与向量等）。灌库与后续「仅查询」必须使用**同一路径**。默认：仓库内 `rag_storage_pipeline`。 |
| `--parser-output-dir` | MinerU / 解析器输出目录。默认：仓库内 `output/pipeline_parse`。 |
| `--parse-method` | 解析方式（如 `auto`、`ocr`、`txt`）。默认读取环境变量 `PARSE_METHOD`，未设置则为 `auto`。 |
| `--recursive` / `--no-recursive` | 是否递归子目录查找文件。默认：**递归**。 |
| `--limit N` | 最多处理 **N** 个文件；**0** 表示不限制（全部）。 |
| `--skip-multimodal` / `--no-skip-multimodal` | 文本入库后是否**跳过**多模态处理器。默认：**跳过**（`True`）。需要 **表格 / 图片 / 公式** 走多模态处理器时，灌库使用 **`--no-skip-multimodal`**，详见下文 **「多模态灌库」**。 |
| `--query-mode` | LightRAG 查询模式。默认读取 `RAG_QUERY_MODE`，未设置则为 **`mix`**。 |
| `--ingest-only` | 只执行解析 + 灌库，**不**进入问答。 |
| `--query-only` | **不**解析、**不**灌库；从 `-w` 加载已有数据，再进行 `--query` 或交互对话。与 `--ingest-only` **互斥**。 |
| `--query "..."` | 灌库后（或 `--query-only` 时）只提问 **一次**并打印答案后退出；若为空则进入**交互模式**。 |
| `--mineru-download-models` | 在解析前执行 `mineru-models-download` 拉取 pipeline 权重（**仅在非 `--query-only`** 时生效）。 |

### 关于 `-w`（working dir）

`-w` 指向的是一套 **LightRAG 工作空间**。同一知识库实验应对固定使用同一个目录；换目录相当于另一套库。**仅查询**（`--query-only`）时也必须指向**当初灌库时**使用的同一 `-w`。

### `--query` 与交互模式

- 若 **`--query` 非空**：执行一次 `aquery`，打印结果后退出（除非前面已因 `--ingest-only` 退出）。
- 若 **未提供 `--query` 或内容为空**：进入 **`Q>`** 交互循环（输入 **`exit` / `quit` / `退出`** 等退出；**空行不退出**，仅再次显示 **`Q>`**）。

`--query-only` 下规则相同：**不带 `--query`** → 交互；**带 `--query`** → 单次问答。

## 环境变量（与脚本强相关）

脚本在 `_build_rag` 中会读取（节选；完整可参考仓库根目录 [`env.example`](../env.example)）：

**LLM**

- `OPENAI_API_KEY` 或 `LLM_BINDING_API_KEY`（必填其一）
- `LLM_BINDING_HOST` 或 `OPENAI_BASE_URL`（兼容 OpenAI API 的网关地址）
- `LLM_MODEL`、`VISION_MODEL`（可选）

**向量 / Embedding**

- `EMBEDDING_BACKEND`：`openai`（默认）或 **`hf`**（本地 Hugging Face / sentence-transformers）
- `EMBEDDING_MODEL`、`EMBEDDING_DIM`（须与所用模型一致；例如 `BAAI/bge-m3` 常为 **1024** 维）
- OpenAI 路径下：`EMBEDDING_API_KEY`（可单独指定）；若设置了 `EMBEDDING_BINDING_HOST`，通常还需配置对应的 `EMBEDDING_API_KEY`
- 本地向量常用：`HF_HOME`（模型缓存目录）
- 模型已完整下载后仍访问 `huggingface.co`：默认会 HEAD 检查/解析；可设 **`HF_EMBED_OFFLINE=1`**（或全局 **`HF_HUB_OFFLINE=1`**）强制仅用本地缓存，避免查询时再连外网
- 本地 `hf` 向量设备：不设则自动选用 **CUDA**（`torch.cuda.is_available()`）或 Apple **MPS**；可用 **`HF_EMBED_DEVICE`**（或 **`EMBEDDING_DEVICE`**）设为 `cuda`、`cpu`、`mps` 等覆盖。要用 NVIDIA 显卡需安装 **CUDA 版 PyTorch**（仅 CPU 的 `torch` 不会启用 CUDA）

**解析器 / MinerU**

- `PARSER`（默认 `mineru`）、`PARSE_METHOD`
- `MINERU_LANG` / `OCR_LANG`、`MINERU_BACKEND`、`MINERU_SOURCE`、`MINERU_DEVICE` 等会传入解析调用

**检索重排序（Rerank）**

- LightRAG 在 **`RERANK_BY_DEFAULT=true`** 时会对向量检索到的 chunk 调用 **`rerank_model_func`**；若未配置该函数，会打警告并跳过重排。本脚本的 **`_build_rag`** 已根据 **`RERANK_BINDING`** 注入（`jina` / `cohere` / `aliyun` / **`hf` 本地 CrossEncoder** / 不设或 **`none`** 关闭）。变量说明见根目录 **`env.example`** 的 `### Rerank` 段；分步说明见 **[model-download-ingest-query.md](./model-download-ingest-query.md)** 第 3.3 节。

灌库与 `--query-only` 查询时，**LLM 与 Embedding 的配置应与灌库时保持一致**，否则检索与向量空间可能不匹配。

**减少「多本手册互相串台」**

- **`mix`** 会合并图谱与向量 chunk，两本 PDF 若都含「残胶 / 封边机」等词，容易把《自动封边机…》片段一并召回到上下文。可选做法：
  - **问法**：在问题里写明依据哪份资料（例如「仅根据《封边机连线项目维护保养手册》」）。
  - **`.env`（流水线脚本）**：**`RAG_QUERY_HL_KEYWORDS`**（英文逗号分隔）传入 LightRAG 的 **`hl_keywords`**，偏向含这些词的实体/块；**`RAG_QUERY_USER_PROMPT`** 注入 **`user_prompt`**，约束模型只引用与某手册相关的内容（见根目录 **`env.example`** 中 `### Pipeline script only: query steering`）。
  - **检索预算**：略降 **`CHUNK_TOP_K`** / **`TOP_K`**、略提高 **`COSINE_THRESHOLD`**，减少弱相关跨文档 chunk；或略提高 **`MIN_RERANK_SCORE`** 过滤低分 chunk（需结合 LightRAG 文档）。
  - **知识库拆分**：不同产品线手册用 **不同 `-w`** 灌库，查询时只加载对应库，从根上避免串文档。

**多模态灌库（表格 / 图片 / 公式）**

- 默认 **`--skip-multimodal`**（即跳过多模态）：入库快、LLM 调用少；纯文本路径下 **`insert_content_list`** 会把 **`type: table`** 的 **`table_body` / `content.html`** 拼进正文再索引（便于表格检索），但不会走 **TableModalProcessor** 等增强流程。
- 需要 **多模态处理器**（如对表格生成描述、单独建多模态 chunk 等）时，灌库命令加 **`--no-skip-multimodal`**。此时 **`_build_rag`** 会按 `.env` 打开处理器开关（未设置时默认均为 **true**）：
  - **`ENABLE_TABLE_PROCESSING`**：表格
  - **`ENABLE_IMAGE_PROCESSING`**：图片（可能走 **`VISION_MODEL`**）
  - **`ENABLE_EQUATION_PROCESSING`**：公式  
  若只想做表格、暂时关闭图片/公式，可在 `.env` 中设 **`ENABLE_TABLE_PROCESSING=true`**，另两项 **`false`**。
- **多模态灌库依赖可用的 LLM**（表格描述等），耗时与费用高于默认路径；灌库前请确认 **`LLM_BINDING_HOST`** 与网络/代理可达。
- 从「仅文本默认灌库」改为「多模态灌库」或调整 **`ENABLE_*`** 后，建议 **新 `-w` 或清空旧库后重灌**，避免索引语义混用。

## 示例

### 1. 全流程：解析 + 灌库 + 交互问答

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./my_documents \
  -w ./rag_storage_run
```

### 2. 只灌库（稍后单独查询）

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./my_files \
  -w ./rag_storage_run \
  --ingest-only
```

### 3. 灌库结束后自动问一个问题再退出

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./my_documents \
  -w ./rag_storage_run \
  --query "文档中的主要结论是什么？"
```

### 4. 仅查询（加载已有 `rag_storage_run`，进入交互）

先前需已用相同 `-w` 灌库。

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --query-only \
  -w ./rag_storage_run
```

交互模式下退出：输入 **`exit` / `quit` / `bye` / `/exit` / `/quit` / `:q` / `!q` / `退出` / `再见`**；**空行仅相当于再出一行 `Q>`**（与终端行为类似）；也可 **Ctrl+C**（部分环境下 **Ctrl+Break**）结束。

### 5. 仅查询：单次提问后退出

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --query-only \
  -w ./rag_storage_run \
  --query "上个季度营收口径在哪里说明？"
```

### 6. 调试：只处理前 2 个文件、关闭子目录递归

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./pdfs \
  -w ./rag_storage_try \
  --limit 2 \
  --no-recursive \
  --ingest-only
```

### 7. 首次下载 MinerU pipeline 权重后再灌库

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./pdfs \
  -w ./rag_storage_run \
  --mineru-download-models \
  --ingest-only
```

### 8. 灌库并启用多模态（表格 / 图片 / 公式）

```bash
uv run python scripts/rag_pipeline_parse_graph_chat.py \
  --input-folder ./my_pdfs \
  -w ./rag_storage_run \
  --ingest-only \
  --no-skip-multimodal
```

仅表格、关闭图片与公式时，在 `.env` 中设置 **`ENABLE_TABLE_PROCESSING=true`**，**`ENABLE_IMAGE_PROCESSING=false`**，**`ENABLE_EQUATION_PROCESSING=false`** 后再执行上述命令。

```powershell

```

## 常见问题

1. **`--input-folder is required unless --query-only`**  
   除 `--query-only` 外都必须指定 `--input-folder`。

2. **`Choose either --query-only or --ingest-only`**  
   两个开关不能同时使用。

3. **查询结果异常或报错**  
   确认 `--query-only` 的 `-w` 与灌库时一致，且 `.env` 中 Embedding 维度、后端与灌库时相同。

4. **多模态灌库报 LLM 连接错误**  
   **`--no-skip-multimodal`** 会额外调用 LLM（如表格描述）。请检查 **`LLM_BINDING_HOST`**、代理与网络。

5. **Office 文档**  
   解析 Office 格式可能需要本机安装 **LibreOffice**（见主 README 说明）。

- 构建 `RAGAnything` / `LightRAG`：`scripts/rag_pipeline_parse_graph_chat.py` 中 `_build_rag`
- 批量解析与入库：`scripts/rag_pipeline_parse_graph_chat.py` 中 `_ingest_folder`（内部调用 `rag.parse_document`、`rag.insert_content_list`）

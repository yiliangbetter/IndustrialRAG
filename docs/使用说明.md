# 使用说明（克隆后快速上手）

本文档面向**从 GitHub 克隆本仓库后首次部署**的同事，目标是在最短时间内完成：**装环境 → 配 `.env` → 灌库 → 浏览器或命令行问答**。

> 本仓库在 [RAG-Anything](https://github.com/HKUDS/RAG-Anything) / LightRAG 基础上，增加了**南兴知识库问答 Web 界面**、**机型检索规则**、**流式进度展示**等工业场景定制。上游通用说明仍见根目录 [`README_zh.md`](../README_zh.md)。

---

## 1. 你能用这个工程做什么

| 能力 | 说明 |
|------|------|
| PDF / Office 解析灌库 | MinerU 解析文档，写入 LightRAG 知识图谱 + 向量库 |
| 图谱 + 向量混合问答 | 默认 `mix` 模式，结合 KG 与 chunk 检索 |
| 浏览器问答 | **南兴知识库问答助手**（`scripts/rag_web_server.py`） |
| 命令行问答 / 调试 | `scripts/rag_pipeline_parse_graph_chat.py` |
| 机型过滤 | 多本手册混库时，按问题自动排除无关 PDF（见 [`新增PDF与机型检索规则说明.md`](新增PDF与机型检索规则说明.md)） |

## 2. 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 或 Linux（文档以 Windows PowerShell 为例） |
| Python | **≥ 3.10** |
| 包管理 | 推荐 **[uv](https://github.com/astral-sh/uv)**（项目自带 `.venv` 管理） |
| Git | 克隆与分支切换 |
| LLM | 至少一个 **OpenAI 兼容 API**（如 DashScope、自建网关等），需 API Key |
| 磁盘 | 建议预留 **10GB+**（Python 依赖 + Hugging Face 模型 + 知识库） |
| GPU | 可选；本地 Embedding / Rerank（`EMBEDDING_BACKEND=hf`）有 NVIDIA GPU 更快 |
| LibreOffice | 解析 `.doc/.docx/.ppt` 等 Office 时可能需要（见主 README） |

```powershell
git clone https://github.com/yiliangbetter/IndustrialRAG.git
cd IndustrialRAG
```

若远程仍指向旧地址 `RAG-Anything.git`，克隆后同样可用；GitHub 会提示新地址为 `IndustrialRAG`。

```powershell
git checkout lhq-rag-dev

```

## 4. 安装依赖

在**仓库根目录**（含 `pyproject.toml` 的目录）执行：

```powershell
# 基础依赖 + 本地向量 + Web 界面（推荐一次性装齐）
uv sync --extra local-embed --extra web
```

| extra | 作用 |
|-------|------|
| （默认） | LightRAG、MinerU、核心 RAG 能力 |
| `local-embed` | 本地 Hugging Face 向量模型（`sentence-transformers`） |
| `web` | FastAPI + uvicorn，浏览器问答界面 |

验证安装：

```powershell
uv run python -c "import lightrag; print('ok')"
```

## 5. 配置 `.env`

### 5.1 创建配置文件

```powershell
copy env.example .env
# 用编辑器打开 .env，填入 API Key 与路径
```

**重要：** 所有脚本从**仓库根目录**加载 `.env`；请在根目录执行 `uv run python scripts/...`。

### 5.2 最小必填项

至少需要配置 **LLM**，否则无法灌库（实体抽取）或问答：

```ini
# LLM（OpenAI 兼容接口）
LLM_BINDING=openai
LLM_BINDING_HOST=https://your-api-gateway/v1    # 例如 DashScope 兼容地址
LLM_BINDING_API_KEY=sk-xxxxxxxx
LLM_MODEL=qwen-plus                              # 按实际模型名填写
```

### 5.3 推荐配置（本地向量 + 本地 Rerank）

本仓库 `env.example` 末尾有**现场常用示例**，可按需启用：

```ini
EMBEDDING_BACKEND=hf
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_DIM=1024
HF_HOME=D:/path/to/your/.hf_cache          # 模型缓存目录，建议用绝对路径
HF_EMBED_OFFLINE=1                         # 模型已下载后，避免联网检查

RERANK_BY_DEFAULT=true
RERANK_BINDING=hf
RERANK_MODEL=BAAI/bge-reranker-base

RAG_QUERY_MODE=mix
RAG_QUERY_DOC_FILTER=true                  # 机型文档过滤（建议开启）

# 检索与 mix 模式 token 预算（可按需调整）
TOP_K=20
CHUNK_TOP_K=30
MIN_RERANK_SCORE=0.22
MAX_TOTAL_TOKENS=52000

# Web 界面
RAG_WEB_WORKING_DIR=rag_storage_run
RAG_WEB_PORT=8765
```

完整变量说明见 [`env.example`](../env.example)；分步下载模型见 [`model-download-ingest-query.md`](model-download-ingest-query.md)。

### 5.4 离线 / 内网

- **tiktoken**：首次可能联网下载，内网需配置 `TIKTOKEN_CACHE_DIR`，见 [`offline_setup.md`](offline_setup.md)
- **Hugging Face 模型**：提前下载到 `HF_HOME`，并设 `HF_EMBED_OFFLINE=1`

## 6. 下载模型（首次，使用本地 HF 时）

若 `.env` 中 `EMBEDDING_BACKEND=hf` 或 `RERANK_BINDING=hf`，需先拉取模型（只需一次）：

```powershell
# 示例：Embedding + Rerank（路径按你的 HF_HOME 调整）
huggingface-cli download BAAI/bge-m3 --local-dir .hf_cache/hub/models--BAAI--bge-m3/snapshots/main
huggingface-cli download BAAI/bge-reranker-base --local-dir .hf_cache/hub/models--BAAI--bge-reranker-base/snapshots/main
```

MinerU 解析 PDF 的权重在**首次灌库**时也可能下载，或预先执行：

```powershell
uv run python scripts/rag_pipeline_parse_graph_chat.py --mineru-download-models --query-only -w rag_storage_run
```

（`--query-only` 仅避免要求 `--input-folder`，主要触发模型下载逻辑。）

网络慢时可临时设代理，见 [`model-download-ingest-query.md`](model-download-ingest-query.md) 第 0.5 节。

## 7. 灌库（建立知识库）

### 7.1 准备文档

将 PDF 等文件放入例如 `my_documents/`（可自建目录）：

```
my_documents/
  封边机连线项目维护保养手册.pdf
  ...
```

### 7.2 命令行灌库（推荐首次全量）

**`-w`（工作目录）** 是知识库唯一标识：灌库与查询必须指向**同一路径**。

```powershell
uv run python scripts/rag_pipeline_parse_graph_chat.py `
  --input-folder ./my_documents `
  -w ./rag_storage_run `
  --ingest-only
```

- 默认 **`--skip-multimodal`**：文本优先，速度较快，适合维护手册类 PDF
- 首次灌库耗时较长（解析 + LLM 抽实体 + 向量化），请耐心等待
- 仅追加新 PDF：把**新文件单独放一文件夹**，对同一 `-w` 再执行一次 `--ingest-only`

### 7.3 Web 界面灌库（可选）

先启动 Web 服务（见下一节），在左侧「上传灌库」拖拽文件。  
`RAG_WEB_WORKING_DIR` 必须与 CLI 的 `-w` **一致**（默认 `rag_storage_run`）。

### 7.4 灌库后检查

- 目录 `rag_storage_run/` 下应出现图谱、向量等文件
- 可做一次试问答（见第 8 节）

**注意：** 更换 `EMBEDDING_MODEL` / `EMBEDDING_DIM` 后，应对**新 `-w` 全量重灌**，勿与旧向量混用。

## 8. 问答

### 8.1 浏览器（南兴知识库问答助手）

```powershell
$env:RAG_WEB_WORKING_DIR = "rag_storage_run"   # 与灌库 -w 一致
uv run python scripts/rag_web_server.py
```

浏览器打开：**http://127.0.0.1:8765/**

- 侧栏查看「就绪 / 工作目录 / RAG 模式」
- 选择 **RAG模式**（默认 `mix`），输入问题
- 流式显示：检索进度 → 检索范围 → 思考过程（可折叠）→ 回答（Markdown）

前后端原理见 [`网页问答界面.md`](网页问答界面.md)。

### 8.2 命令行交互问答

```powershell
uv run python scripts/rag_pipeline_parse_graph_chat.py `
  --query-only `
  -w ./rag_storage_run
```

出现 `Q>` 后输入问题；输入 `exit` / `退出` 结束。

单次提问：

```powershell
uv run python scripts/rag_pipeline_parse_graph_chat.py `
  --query-only `
  -w ./rag_storage_run `
  --query "高速智能封边机输送链条如何保养？"
```

### 8.3 调试检索（不改代码）

查看最终送给 LLM 的 chunk 列表：

```powershell
uv run python scripts/dump_query_context.py -w rag_storage_run `
  --out docs/my_dump.txt "你的问题"
```

## 9. 日常使用：新增 PDF

1. 新 PDF 放入单独文件夹（或 Web 上传）
2. 对**同一 `-w`** 执行灌库（CLI 或 Web）
3. **无需改 `.env`** 即可问新书内容
4. 若新 PDF 代表**新机型**且与旧手册「串台」，需维护 [`scripts/query_doc_steering.py`](../scripts/query_doc_steering.py) 中的 `MACHINE_PROFILES`

详见 [`新增PDF与机型检索规则说明.md`](新增PDF与机型检索规则说明.md)。

## 11. 常见问题

| 现象 | 处理 |
|------|------|
| Web 侧栏「就绪：否」 | 看错误提示；检查 `.env`、API Key、`uv sync --extra web --extra local-embed` |
| `Set OPENAI_API_KEY or LLM_BINDING_API_KEY` | 在 `.env` 配置 `LLM_BINDING_API_KEY` |
| 查询结果乱 / 像没灌库 | 确认 `-w` 与灌库时一致；Embedding 模型是否与灌库时相同 |
| 答案引用了错误手册 | 开启 `RAG_QUERY_DOC_FILTER`；检查 `query_doc_steering.py`；见检索范围提示条 |
| 改规则后答案不变 | 设 `ENABLE_LLM_CACHE=false` 或运行 `clear_query_llm_cache.py -w rag_storage_run` |
| 灌库很慢 | 正常；PDF 多页 + LLM 抽实体。可 `--limit 1` 试跑单文件 |
| HF 模型仍联网 | 设 `HF_EMBED_OFFLINE=1`，确认 `HF_HOME` 下已有 snapshot |
| Office 解析失败 | 安装 LibreOffice；或先转为 PDF |

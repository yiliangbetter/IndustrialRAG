# 实现方案文档模板

本仓库撰写 **功能实现说明 / 实现方案** 时统一用此结构。可参考现成范例：

- [`多轮问答实现方案.md`](多轮问答实现方案.md)
- [`查询配图实现说明.md`](查询配图实现说明.md)

复制下方「正文骨架」到新文件，按章节填写；删去用不到的节。

---

## 写作原则

### 说人话

- 先解释 **是什么、解决什么问题**，再写模块名与函数名。
- 库内部机制（hook、patch、第三方库函数）用 **日常比喻** 说明，例如：
  - *Hook*：问答期间 **临时包一层** 库函数，做完额外逻辑再 **还原**。
  - *某内部函数*：库在某某步骤里 **合并/截断** 候选数据，得到 **最终送给 LLM 的那一份**。
- **避免** 未解释就写「X patch 了 Y 的 Z」——读者应能不看代码也懂大意。

### 关键术语单独成章

第 2 章 **关键术语** 是模板核心。文中反复出现的函数、字段、配置名，在此用统一格式说明：

```markdown
### 2.N `函数或概念名`

**是什么**：一句话定义。

**做什么**：（编号列表，步骤清晰）

**用在哪里** / **返回什么**：（表格可选）

**不是什么** / **注意**：（常见误解，一行即可）
```

每个术语之间用 `---` 分隔，避免挤成一大段。

### 不写测试个案

- 实现文档描述 **通用机制**，不写「Q3 某某题」「某次 dump 现象」等调试个案。
- 验收用例、批测命令可放在 **测试与验证** 一节，只链到 [`测试问题.txt`](测试问题.txt) 等外部文件，不在正文展开。

### 篇幅与交叉引用

- 全链路摘要放在 [`问答全流程图.md`](问答全流程图.md)；专题文档 **只写本功能**，开头链到关联文档。
- 不写「实施阶段 checklist」「与原始需求逐条对照」等已落地功能的冗余章节，除非功能仍在设计中。
- 章节之间用 `---` 分隔；列表、表格优先于长段落。

### 流程图

- 至少 1 张 **总览图**（架构或时序）；复杂分支可再加 1 张。
- 默认 `flowchart TB` 纵向排版；节点文字过长用 `<br/>` 换行。
- 可选 mermaid init 增大字号：`%%{init: {'themeVariables': {'fontSize': '16px'}}}%%`

### 版本脚注

文末一行：`*文档版本：vX.Y · YYYY-MM-DD*`

## 章节取舍

| 章节 | 何时省略 |
|------|----------|
| §5 接口 | 纯灌库/纯脚本、无 Web API |
| §6 配置 | 无可配 env |
| §8 废弃 | 新功能无历史包袱 |
| §4 架构 | 极简单工具可并入 §3 |

多轮问答类功能：§3 写门控规则，§5 写 SSE。  
灌库 + 查询类功能：§3 写灌库，§4 写查询挂接，§7 写 dump 字段。

## 1. 背景：要解决什么问题

智能客服场景里，用户输入分两类：

| 类型 | 代表集 | 业务期望 |
|------|--------|----------|
| **完整问句** | `shili17`（17 条维护保养测试例） | **不澄清**，直接检索作答 |
| **口语碎片 / 报警短句** | `green8`（Excel 技术问题 sheet A 列浅绿 8 题） | **需澄清**，让用户说明到底想问什么 |

核心问题：**能否用向量相关度分数（query / high / low）自动区分这两批？** 以便日后接入澄清逻辑时，shili17 零误伤、green8 全命中。

## 2. 打分方法：Naive Relevance

### 2.1 做什么

对每道题算三个 **chunk 向量 cosine 最高分**（粗检索，不走 rerank / KG）：

| 符号 | 含义 |
|------|------|
| **q** | 用**整句 query** 检索 `chunks_vdb` 的最高 cosine |
| **h** | 用 LLM 抽取的 **high_level 关键词**（逗号拼接）检索的最高 cosine |
| **l** | 用 LLM 抽取的 **low_level 关键词** 检索的最高 cosine |

### 2.2 与 `COSINE_THRESHOLD=0.33` 的关系

- **同一套**：同库、bge-m3、余弦相似度，与 LightRAG 向量召回门槛同源。
- **报告主分**：probe 时把 threshold 暂设为 **0**，取 top_k 内 **max cosine**（低于 0.33 也有分）。
- **`hits_above_threshold`**：额外统计实际超过 0.33 能召回几条（naive 能否过拒答线）。

### 2.3 工作库与参数

- 库：`data/rag_storage`（987 chunks）
- `COSINE_THRESHOLD=0.33`，`probe_top_k=20`
- 代码：`raganything/naive_relevance.py`
- 批量 CLI：`scripts/score_query_relevance.py`

### 2.4 复现命令

```bash
# 17 测试例
uv run python scripts/score_query_relevance.py -w data/rag_storage \
  --source shili17 --limit 17 \
  --out logs/relevance_shili17.jsonl \
  --report logs/relevance_shili17_report.txt

# 29 技术话术（母集）
uv run python scripts/score_query_relevance.py -w data/rag_storage \
  --source voice29 \
  --out logs/relevance_voice_tech29.jsonl \
  --report logs/relevance_voice_tech29_report.txt

# Excel 绿标 8 题
uv run python scripts/score_query_relevance.py -w data/rag_storage \
  --source green8 \
  --out logs/relevance_voice_green8.jsonl \
  --report logs/relevance_voice_green8_report.txt
```

## 5. 讨论一：单靠阈值 / 规则能否分开？

### 5.1 问题（原话）

> 结合 query、high、low，有没有办法把 shili17 和 green8 区分开？目的是以后加澄清逻辑时，shili17 都不澄清，green8 都要让用户进一步澄清。

### 5.2 单阈值 `query < T → 澄清`

扫描 T 从 0.58 到 0.77 的结果（节选）：

| T | shili 误澄清 | green 命中 |
|---|-------------|------------|
| 0.60 | 0/17 | 0/8 |
| 0.65 | 0/17 | 2/8 |
| 0.66 | 1/17 | 3/8 |
| 0.70 | 2/17 | 5/8 |
| 0.76 | 9/17 | 7/8 |

**不存在**某个 T 使 shili=0 误伤且 green=8 全命中（green 含 0.854 高分短句，shili 最低 0.658）。

### 5.3 「网格搜索」是什么意思？

系统地穷举多类规则及参数组合，对 25 题回放，看能否 **shili 0 误伤 + green 8 全中**。

试过的规则类型：

```text
若 query < T              → 需要澄清
若 min(q,h,l) < T         → 需要澄清
若 spread > S             → 需要澄清   （spread = max(q,h,l) − min(q,h,l)）
若 关键词失真             → 需要澄清   （|h−q|>0.10 或 |l−q|>0.08）
```

把 T、S、是否启用失真、多条 OR 组合等在合理范围内排列组合 → **没有任何组合达到完美分离**。

完整数值报告：`logs/clarify_threshold_analysis.txt`  
复现脚本：`scripts/analyze_clarify_threshold.py`

## 6. 讨论二：问法形态（题干长度）

在当前 25 条样本上，**题干长度**可完美分开：

```text
题干长度 < 16  → 需澄清：green 8/8，shili 0/17
题干长度 ≥ 16  → 不澄清：shili 17/17
```

| | shili17 | green8 |
|---|---------|--------|
| 长度范围 | 16–39 字 | 2–10 字 |
| 形态 | 完整问句（怎么/哪些/多久/步骤…） | 口语碎片、报警码 |

**注意**：11–15 字区间无样本，是数据集构造带来的「空隙」，不能指望对所有未来话术泛化，但方向明确：**短句 vs 完整问句** 比 cosine 更有区分力。

## 7. 讨论三：三维坐标 + 分界面（数学方法）

### 7.1 问题（原话）

> 把 q、h、l 看作三维坐标系，每题是一个点，用某种算法形成一个面，把两批题区分开——有没有这样的数学方法？

### 7.2 回答：可以，且这正是经典分类问题

每题 = 点 \((q, h, l)\)；两批 = 两个点云；目标 = 找**分界面**（超平面或曲面）。

### 7.3 纯三维 \((q,h,l)\) 的结果

| 方法 | 几何含义 | 训练集准确率 |
|------|----------|--------------|
| 线性 SVM / 感知机 | 超平面 \(w_1 q + w_2 h + w_3 l + b = 0\) | **21/25（84%）** |
| LDA | 最优线性投影方向 | **21/25** |
| 逻辑回归 | \(P(\text{澄清}\|q,h,l)\) | 同类，无法零误分 |
| QDA / 多项式 SVM | 二次曲面 / 弯曲分界 | **24/25**，仍非完美 |
| 留一交叉验证（3D 线性 SVM） | 每次留 1 题拟合 | **19/25** |

最优线性平面（仅 q,h,l）近似：

\[
-7.81\,q - 9.63\,h - 9.29\,l + 19.11 = 0
\]

**线性 SVM 误分的 4 题：**

| 题 | 实际 | 预测 | 几何原因 |
|----|------|------|----------|
| shili Q14「…多少产品型号？」 | 不澄清 | 误判澄清 | 16 字 + 中等分，落入 green 区域 |
| shili Q17「…哪些步骤要清洁」 | 不澄清 | 误判澄清 | 18 字 + 中等偏高分 |
| green G3「气压报警？」 | 需澄清 | 误判不澄清 | 5 字但 q=0.854，像「正常题」 |
| green G6「变频器异常报警」 | 需澄清 | 误判不澄清 | 7 字 + 中等分，与 shili 重叠 |

**结论**：两批在三维里**线性不可分**；q 重叠区约 **0.658–0.854**，任意平面都会穿过两侧各有点。

### 7.4 加第四维：题干长度 \(L\)

四维线性 SVM \((q, h, l, L)\)：

\[
-0.0013\,q + 0.0069\,h - 0.0014\,l - 0.33\,L + 4.33 = 0
\]

- 训练集：**25/25**
- 留一交叉验证：**25/25**
- \(L\) 系数最大 → 分界主要在「长度轴」上切，q/h/l 只做微调

与「长度 < 16 完美分离」结论一致。但样本仅 25 条，四维拟合泛化需谨慎。

### 7.5 几何直觉（文字版）

```
         (q,h,l) 空间
    ┌─────────────────────────┐
    │  shili17：偏长句、偏高 q  │
    │         ╲               │
    │          ╲  重叠区       │
    │  green8： ╲ q≈0.66~0.85 │
    │  极短句、   ╲ 有高有低    │
    │  q 分散      ╲           │
    └─────────────────────────┘
    → 任意平面都会误分至少 4 题
    → 需加「长度」维或形态/名单
```

## 8. 讨论四：决策树（Decision Tree）

### 8.1 问题

> 用 decision tree 怎么样？

决策树把特征空间切成一块块矩形区域，输出 **if-then 规则**，比超平面更直观，适合给业务看。

### 8.2 与线性 SVM 对比（本批 25 题）

| 特征 | 决策树训练集 | 决策树 LOOCV | 线性 SVM LOOCV |
|------|-------------|--------------|----------------|
| 仅 **(q, h, l)** | **25/25**（可拟合到零误分） | **15/25** | **19/25** |
| **(q, h, l, len, …)** | 25/25 | **25/25** | 25/25 |

要点：

- **只用 q/h/l**：树能把 25 题全部记住，但留一法只有 **15/25**，**比线性 SVM 更差**——典型过拟合（样本少、边界锯齿多）。
- **加上题干长度**：深度 1 的树自动学成一条规则，与手动分析一致。

### 8.3 只用 (q,h,l) 时树学到了什么（过拟合版，勿直接上线）

```text
若 h ≤ 0.74：
    若 l ≤ 0.71 → 需澄清
    若 l > 0.71：
        若 q ≤ 0.76 → 不澄清
        否则 → 需澄清
若 h > 0.74：
    若 q ≤ 0.84 → 不澄清
    若 0.84 < q ≤ 0.88 → 需澄清   ← 为「气压报警？」(0.854) 硬掰的叶子
    若 q > 0.88 → 不澄清
```

训练集 100% 正确，但换一题或留一验证就崩——**0.74、0.71 等阈值是死记这 25 点，不是稳定规律**。

限制 **depth=2**、仅用 (q,h,l) 时 LOOCV **19/25**（与线性 SVM 同档），仍解决不了「气压报警？」这类高分短句。

### 8.4 加上长度后（depth=1，最稳）

```text
若 len ≤ 13 → 需澄清
若 len > 13 → 不澄清
```

- 训练集：**25/25**
- 留一交叉验证：**25/25**

shili 最短 **16** 字，green 最长 **10** 字，故 **10 < 阈值 < 16** 均可完美分开（树选了 13；与「<16」本质相同）。

### 8.5 决策树适合怎么用

**适合：**

- 需要 **if-then 规则** 给产品/业务看（比「-7.81q - 9.63h…」直观）
- 特征含 **长度、形态** 等可解释量
- 控制 **max_depth=2~3、min_samples_leaf≥3**，避免死记 25 点

**不适合：**

- 只有 q/h/l 三维、样本仅 25 条 → 深树训练满分、泛化差
- 把 sklearn 拟合出的整棵树原样写进线上（叶子阈值会随数据抖动）

### 8.6 与工程 pipeline 的关系

不必部署 ML 树；决策树实验验证了 **手写浅树** 的结构：

```text
1. 命中 green8 名单？              → 澄清
2. len ≤ 13（或 env 配 15）？       → 澄清
3. len ≥ 16 且像完整问句？          → 不澄清
4. q < 0.70 或 spread > 0.12？     → 澄清（辅助）
5. 否则                           → 不澄清
```

**一句话**：决策树思路对、规则好懂；纯 (q,h,l) 上不如线性 SVM 稳且易过拟合。加上题干长度后，浅树（甚至 depth=1）LOOCV 满分——澄清门控更像 **「形态分类树」**，不是 **「向量分数分类树」**。

## 9. 推荐澄清门控（三层）

基于上述实验（含第 7 节超平面、第 8 节决策树），建议 **不要单靠 q/h/l**，采用分层 pipeline：

### 第 1 层：名单（最稳）

```text
若 standard_question ∈ voice_script_green8.json → 强制澄清
```

覆盖 Excel 绿标 8 题，不依赖分数。

### 第 2 层：问法形态

满足以下可 **跳过澄清**：

- 长度 ≥ 16（可 env 配置 `CLARIFY_MAX_CHARS=15`）
- 含完整问法词：怎么 / 哪些 / 多久 / 步骤 / 适用于 等
- 非纯报警码短句

在本批数据上：shili17 **17/17** 通过。

### 第 3 层：naive 向量辅助（灰色地带）

未命中 1、2 层时，用 q/h/l：

| 信号 | 建议 | 本批表现 |
|------|------|----------|
| `query < 0.70` | 澄清候选 | 抓到部分 green，误伤 shili Q14/Q16 |
| `spread > 0.12` | 澄清候选 | green G3/G4；误伤 shili Q8 |
| `\|h−q\|>0.10` 或 `\|l−q\|>0.08` | 澄清候选 | 关键词失真 |

**主分用 query**；high/low 作失真对照，不宜单独作澄清条件。

### 默认 pipeline（伪代码）

```python
def needs_clarification(query: str, relevance: dict) -> bool:
    if match_green8_or_short_utterance_registry(query):
        return True
    if len(query) >= 16 and looks_like_full_question(query):
        return False
    q = primary_relevance_score(relevance)
    h, l = ...  # from relevance payload
    spread = max(q, h, l) - min(q, h, l)
    if q < env_float("CLARIFY_QUERY_MAX", 0.70):
        return True
    if spread > env_float("CLARIFY_SPREAD_MIN", 0.12):
        return True
    if keyword_distorted(relevance):
        return True
    return False
```

回放本批：Step1 单独 → green **8/8**；Step2 单独 → shili **17/17**；两层叠加最稳。

## 10. 一句话总结

| 信号 / 方法 | 能否承担「澄清 vs 不澄清」二分 | 说明 |
|-------------|-------------------------------|------|
| 仅 q / h / l | **不能**（线性 SVM ~84%，决策树 LOOCV 60%） | 反映库内相似度；深树易过拟合 |
| q/h/l + 长度 L | **本批可**（SVM / 浅树 LOOCV 25/25） | 样本少，泛化保守 |
| 题干长度 / 形态 | **本批最强**（<16 字完美分离） | 11–15 字无样本空隙 |
| 决策树（depth=1 + len） | **本批可**，规则最直观 | `len≤13→澄清`，勿部署深树 |
| green8 名单 | **最稳** | 业务标定，零误伤 |

**工程建议**：名单 + 形态门控（手写浅树）为主，\((q,h,l)\) 作辅助；低置信度再走 LLM 澄清。不必上线 sklearn 拟合树。

## 12. 对话脉络（Q&A 摘要）

1. **建立打分能力** — 在 `OK0614_no_clarify` 基线上实现 naive relevance，批量跑 shili17 与 voice29，生成报告与 HTML 图表。
2. **提取 green8** — 从 Excel A 列浅绿提取 8 题，建立 `voice_script_green8.json` 与子报告。
3. **能否用 q/h/l 区分？** — 网格搜索单阈值与组合规则 → **无法** shili 0 误伤 + green 8 全中；**长度**可完美分离。
4. **「网格搜索」什么意思？** — 穷举 q<T、min<T、spread>S、失真等规则参数，对 25 题回放找完美分界。
5. **三维坐标 + 分界面？** — 线性 SVM 在 (q,h,l) 上 **21/25**，本质不可分；加长度维 **25/25**；推荐三层门控。
6. **决策树怎么样？** — 纯 (q,h,l) 训练满分但 LOOCV **15/25**（过拟合）；加 len 后 depth=1 规则 `len≤13→澄清`，LOOCV **25/25**；建议用手写浅树，不部署拟合深树。
